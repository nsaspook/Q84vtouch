\doxysubsection{Detailed Description}
Documentation of everything you need to know to use the MQTT-\/C client. 

This module contains everything you need to know to use MQTT-\/C in your application. For usage examples see\+:
\begin{DoxyItemize}
\item \doxylink{simple_publisher_8c-example}{simple\+\_\+publisher.\+c}
\item \doxylink{simple_subscriber_8c-example}{simple\+\_\+subscriber.\+c}
\item \doxylink{reconnect_subscriber_8c-example}{reconnect\+\_\+subscriber.\+c}
\item \doxylink{bio_publisher_8c-example}{bio\+\_\+publisher.\+c}
\item \doxylink{openssl_publisher_8c-example}{openssl\+\_\+publisher.\+c}
\end{DoxyItemize}

\begin{DoxyNote}{Note}
MQTT-\/C can be used in both single-\/threaded and multi-\/threaded applications. All the functions in \doxylink{group__api}{API} are thread-\/safe. 
\end{DoxyNote}

\begin{DoxyNote}{Note}
{\ttfamily sockfd} is a non-\/blocking TCP connection. 

If {\ttfamily sendbuf} fills up completely during runtime a {\ttfamily MQTT\+\_\+\+ERROR\+\_\+\+SEND\+\_\+\+BUFFER\+\_\+\+IS\+\_\+\+FULL} error will be set. Similarly if {\ttfamily recvbuf} is ever to small to receive a message from the broker an MQTT\+\_\+\+ERROR\+\_\+\+RECV\+\_\+\+BUFFER\+\_\+\+TOO\+\_\+\+SMALL error will be set. 

A pointer to \doxylink{structmqtt__client_aca624b149b55e16f67bfbec79babd357}{publish\+\_\+response\+\_\+callback\+\_\+state} is always passed as the {\ttfamily state} argument to {\ttfamily publish\+\_\+response\+\_\+callback}. Initializes an MQTT client and enables automatic reconnections. 

An alternative to \doxylink{group__api_gaa5dab8a06f016b09c7a5259274b3b3ce}{mqtt\+\_\+init} that allows the client to automatically reconnect to the broker after an error occurs (e.\+g. socket error or internal buffer overflows).

This is accomplished by calling the {\ttfamily reconnect\+\_\+callback} whenever the client enters an error state. The job of the {\ttfamily reconnect\+\_\+callback} is to\+: (1) perform error handling/logging, (2) clean up the old connection (i.\+e. close client-\/\texorpdfstring{$>$}{>}socketfd), (3) \doxylink{group__api_gaf5ae4b5b880431ef1bcd72f343de9ac6}{mqtt\+\_\+reinit} the client, and (4) reconfigure the MQTT session by calling \doxylink{group__api_gadbe914e5a9d4f93314c4e7637cb4f7b3}{mqtt\+\_\+connect} followed by other API calls such as \doxylink{group__api_gaea5da9b546f6e91eb77c9eff9c478de5}{mqtt\+\_\+subscribe}.

The first argument to the {\ttfamily reconnect\+\_\+callback} is the client (which will be in an error state) and the second argument is a pointer to a void pointer where you can store some state information. Internally, MQTT-\/C calls the reconnect callback like so\+:
